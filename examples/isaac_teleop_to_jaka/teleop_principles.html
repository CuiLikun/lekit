§1 系统架构总览

核心设计原则

  • 无 IK：直接发送绝对 TCP 位姿目标给 JAKA SDK 的 Cartesian Servo Move (servo_p)，主机不执行逆运动学
  • Clutch 接合：squeeze 按下时锁存手柄原点和实测 TCP home，后续目标 = home + (grip_current − grip_origin)
  • 头显相对映射：每次接合锁存操作者朝向，保证直觉方向映射，转头不漂移
  • 异步观测：反馈使用独立 SDK 连接，30 Hz 观测不阻塞 8 ms Servo 命令流

数据速率设计

通道频率说明
控制循环 (record loop)30 Hzobs → compute → send_action → record
Servo P 发送125 Hz (8 ms)JAKA SDK 独立线程持续发送最新目标
XR tracking跟随头显Isaac Teleop session.step() 阻塞等待最新帧
Rerun logging异步不限速独立线程，队满时丢弃旧帧

§3 Clutch 接合重映射

Clutch 是系统的核心数学组件。它的目标是：接合瞬间指令位移恒为零，避免操作者手柄位置与机器人 TCP 之间的初始偏移造成跳变。

3.1 基本原理


原点: origin_pos − 位移: delta_pos
delta_rot + TCP目标: home_pos+delta_pos
home_rot*delta_rot p_tcp_target = p_tcp_home + (p_grip_current − p_grip_origin)   ·   R_tcp_target = (R_grip * R_origin⁻¹) * R_home

3.2 为什么用实测 TCP 做 home？

!
关键设计决策
如果使用"上次命令目标"作为 home，机械臂在松开 squeeze 期间因重力下沉或外力接触产生的位移会在下次接合瞬间被纠正——机械臂会以全 Servo 速度回弹到旧目标。使用实测 TCP 做 home 保证了接合第一帧永远是"当前位置零偏移"。

3.3 Clutch 代码实现

class Clutch:
    def engage(self, grip_pos, grip_quat, home_base_T_ee=None):
        # 用实测 TCP 更新 home（如果提供）
        if home_base_T_ee is not None:
            home = np.asarray(home_base_T_ee)
            self._home_pos = home[:3, 3].copy()
            self._home_rot = Rotation.from_matrix(home[:3, :3])
        # 锁存手柄原点
        self._origin_pos = np.asarray(grip_pos).copy()
        self._origin_rot = Rotation.from_quat(np.asarray(grip_quat))

    def rebase(self, grip_pos, grip_quat):
        # home + (grip_current − grip_origin)
        pos = self._home_pos + (grip_pos - self._origin_pos)
        rot_ctrl = Rotation.from_quat(grip_quat)
        rot = (rot_ctrl * self._origin_rot.inv()) * self._home_rot
        return pos, rot.as_quat()

3.4 位置安全限幅

make_xr_device.compute() 内部实施了多层防护：

防护层阈值作用

§4 头显相对坐标映射

4.1 问题

OpenXR anchor (世界坐标系) 在一个会话中基本固定。操作者转身后身体的"前方"在 anchor 中旋转，固定的 base_T_anchor 只在特定朝向有效——转身后就会出现换轴、反向或两个水平轴同时移动。

4.2 解决方案：接合时锁存头显 yaw

身体右移 → JAKA +X  ·  身体前移 → JAKA +Y  ·  身体上移 → JAKA +Z 锁存时机 squeeze 松开（TCP保持，可转身） 按住 squeeze（固定 base_T_anchor，转头不影响 TCP） ↑ 接合边沿：锁存 head yaw 可自由转身/重新站位 固定坐标映射，转身不影响方向直觉 head 跟踪无效 → 保持TCP不动

4.3 为什么不在每帧跟随头显？

i
关键是锁存而非持续跟踪
如果每帧都重新计算 base_T_anchor，手保持不动时仅转头就会改变坐标变换，造成 TCP 在没有手柄输入的情况下漂移。锁存策略在接合期间冻结映射，既保证了方向直觉，又消除了转头干扰。

4.4 姿态控制：lock_pose 与 thumbstick

lock_pose = true (默认)

接合时锁存实测 TCP roll/pitch/yaw 作为姿态基准。手柄移动只控制平移。姿态通过摇杆调节：

  • 摇杆上下 → 调节 pitch
  • 摇杆左右 → 调节 yaw
  • 按住摇杆再左右 → 调节 roll

松开 squeeze 后姿态偏移清零，下次接合从新的实测 TCP 姿态重新开始。

lock_pose = false

手柄方向直接控制 TCP 姿态。使用 RPY 连续分解（参考上一帧避免 2π 跳变）。摇杆偏移叠加在手柄方向之上。

参数默认值
thumbstick_deadband0.15 (15% 死区)
thumbstick_angular_speed0.5 rad/s

§5 控制循环详解

5.1 主循环流程图

5.2 核心组件职责

HoldLatch

当 compute() 返回 None（clutch 未接合）时，在第一个空闲帧锁存当前观测的 TCP 位姿，后续帧返回锁存值。防止控制器在手柄不接合时继续向未达成的目标移动。

TriggerGripperToggle

将模拟 trigger 值转换为每个按压边沿的离散 toggle。首次读取时从观测初始化夹爪位置。防止每个循环帧都翻转夹爪状态。

ControllerButtons

区分短按和长按（默认 1.0 秒）。A 短按=toggle recording，A 长按=discard 重录。B 短按=toggle pause（松开时判断），B 长按=reset robot。

LoopRateMonitor

通过滑动窗口（默认 1 秒）测量控制循环的实际频率。窗口内至少 2 个样本后返回有效值，用于控制面板显示 LOOP Hz。

_send_action_for_clutch_state

Clutch 接合时启用 Servo Move 并发送 action。Clutch 释放时，如果 gripper 目标有变化先发送 gripper 命令，然后退出 Servo Move。返回的 applied action 用于数据集记录。

5.3 相机超时处理

当某个 RealSense 相机超时时，JakaRobot.get_observation() 抛出 JakaCameraTimeoutError（携带已读到的部分观测）。系统：

  1. 捕获异常，提取部分 obs
  2. _reuse_latest_camera_frames() 用该相机的最新有效帧填充缺失流
  3. 如果缓存也为空，调用 read_latest(max_age_ms=MAX) 做最后一次非阻塞尝试
  4. 帧仍可记录（arm 状态是新鲜的），控制面板显示 CAM TIMEOUT N

§9 RerunLogger 异步可视化

9.1 架构

9.2 关键设计

帧合并 (Coalescing)

put_latest() 将队列中所有旧 log 帧替换为最新一帧。当 Viewer 消费慢于录制循环时，自动跳帧而非阻塞录制。

容错隔离

Rerun 是辅助工具。worker 线程的所有异常被静默捕获（仅 debug log），永远不会影响录制循环。失败帧仅计数到 errors 字段。

Episode 标签绘制

每帧 Camera 图像在发送前用 OpenCV 绘制 Episode 号和 RECORDING/PAUSE 状态。白色文字 + 黑色描边，自适应缩放，居中显示。

switch_record()

每个新 episode 创建新的 RecordingStream（新 recording_id），在 Rerun Viewer 中产生独立的录制时间线。Blueprint 在新 recording 中重新发送。

10.2 如何使用 Trace 调试

方向问题

比较 raw_grip (未变换手柄位置) → control_yaw_deg (锁存 yaw) → requested (Clutch 输出)。检查 yaw 变换矩阵是否正确将手柄前向映射到 JAKA +Y。

延迟问题

比较 requested → applied → servo_target → servo_commanded → actual。如果 requested→applied 一致但 actual 滞后，问题在 JAKA NLF 速度轮廓或机械响应。如果 applied≠servo_target，检查 Servo 周期和 queue depth。
